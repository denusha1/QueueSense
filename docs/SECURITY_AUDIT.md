# QueueSense API security audit

Reviewed on 25 November 2026. The review covered the FastAPI and Next.js boundaries, PostgreSQL access, account and patient flows, notification transports, deployment defaults, and the repository lockfiles. Verification used synthetic data and a local isolated PostgreSQL schema.

## Findings and disposition

| Area | Finding and change | Evidence |
| --- | --- | --- |
| Staff authorization | Queue reads, detailed exports and visit-specific planning could reveal records outside the staff member’s duties. Both APIs now use persisted grants. Doctor queue access is limited to their assigned visits. Managers retain summary exports. Patient notification mutations verify the private link, audience and record owner. | [Role matrix](ROLE_PERMISSION_MATRIX.md), [queue queries](../backend/repositories/queue.py), [reporting](../backend/services/reporting.py), [authorization tests](../backend/tests/test_authorization.py) |
| JWT and session security | The app already verified signatures, claim times, issuer and audience before resolving the database session. The verifier now accepts only the protected header produced by the issuer. Authorization uses current database grants even when a signed token contains permission or role claims. Admin account access changes invalidate existing sessions. | [JWT policy](JWT_AUTHENTICATION.md), [verifier](../backend/core/jwt.py), [session query](../backend/repositories/auth.py) |
| Passwords and recovery | Argon2id and rehash-on-login were already in use. Failed login responses conceal account existence. Existing recovery and MFA throttles now send `Retry-After`. Delivery now verifies SMTP certificates and server names in both TLS modes. | [Credential primitives](../backend/core/security.py), [authentication](../backend/services/auth.py), [account service](../backend/accounts.py), [delivery](../backend/delivery.py) |
| CORS and CSRF | FastAPI accepted the first supplied Origin even when the request contained duplicates. Mutations now require one exact configured Origin. Startup validates HTTP(S) origins and requires HTTPS in production. The browser proxy verifies its own host and allowed origin. Browser CORS stays closed. Staff cookies are HttpOnly, with Secure in production and SameSite protection. | [Middleware](../backend/api/middleware.py), [settings](../backend/core/config.py), [browser proxy](../frontend/services/api-proxy.ts), [session cookies](../backend/api/cookies.py) |
| Input and SQL | The reviewed SQL paths bind user values as parameters. Search escapes the `LIKE` wildcards and sort choices select predefined SQL. Pydantic bounds inputs, rejects extra fields and rejects control characters in single-line text. CSV export already prefixes formula-like text and PDF export escapes text for ReportLab. | [Queue repository](../backend/repositories/queue.py), [search](../backend/table_pages.py), [text validation](../backend/schemas/text.py), [export renderer](../backend/services/reports.py) |
| XSS and response isolation | The Next.js proxy previously forwarded successful upstream responses with any media type. It now limits each response to the route’s expected media types and blocks redirects. Browser pages prohibit embedding, base injection, external form submission and embedded objects. API data and QR responses have a restrictive policy. Next.js image optimization is disabled because QueueSense has no callers that use it. | [Proxy](../frontend/services/api-proxy.ts), [frontend headers](../frontend/next.config.ts), [API headers](../backend/api/middleware.py) |
| Abuse and rate limits | Anonymous tracking originally used a mutable list shared by worker threads. The limit now uses a locked sliding window and returns a retry delay. PostgreSQL-backed login, account and kiosk limits remain. The Next.js proxy already bounds request bodies on its browser routes. | [Local limiter](../backend/core/rate_limit.py), [login service](../backend/services/auth.py), [kiosk arrivals](../backend/arrivals.py), [proxy body handling](../frontend/services/api-proxy.ts) |
| Web Push egress | Subscription validation already used a host allowlist. The service now revalidates the endpoint before delivery, disables redirects, and strictly decodes the subscription keys at registration. | [Delivery transport](../backend/delivery.py) |
| Sensitive responses and logs | Staff grants and session IDs are excluded from public auth responses. Doctor queue rows hide internal priority notes and staff directory responses hide unrelated account IDs. Expected failures use sanitized errors, and request error logs use route templates, correlation IDs and exception types. CI now uses the same Uvicorn access-log and proxy-header switches as the container. | [Error handling](../backend/api/errors.py), [queue views](../backend/services/queue_views.py), [CI configuration](../.github/workflows/ci.yml), [container command](../backend/Dockerfile) |

## Remaining risks

- The public patient read quota applies per API process. PostgreSQL backs the authentication limits, but the backend peer bucket can be shared by clients through the proxy. Distributed client quotas, request-size limits on direct ingress and concurrent event-stream limits need deployment-level controls. The Choreo policies, TLS ingress and backend reachability require live verification.
- A patient link grants access to the associated record for as long as the link remains active. Link expiry and revocation for queue tracking need a policy and implementation. Private capabilities can still leak through QR sharing, browser history and hosting logs. Real-data use requires retention rules and a review of small cohorts and voluntary feedback.
- The browser page policy limits where content may be embedded or submitted. A nonce-based script policy remains open because it would change how Next.js renders and caches pages. Review the production ingress content policy and audit third-party scripts before enabling them. [Next.js CSP guidance](https://nextjs.org/docs/app/guides/content-security-policy)
- The single symmetric signing key requires a coordinated issuance and validation rollout at rotation. QueueSense enables MFA for administrators through the existing application workflow. Staff-wide MFA enforcement, external identity federation and secret-manager rotation require deployment decisions.
- Hosted infrastructure, real SMTP and Web Push providers, recovery operations, backup restore and external security testing remain outside the local verification. See [implementation and deployment checks](SECURITY_IMPLEMENTATION.md).
