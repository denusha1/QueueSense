# QueueSense technical decisions

| Decision | Rationale | Trade-off and follow-up |
| --- | --- | --- |
| Keep a modular FastAPI monolith | Queue issuance, lifecycle events and audit writes share a transaction. Next.js remains a separate web process. | Reporting and predictions share API resources. Measure contention before splitting services. [System architecture](SYSTEM_ARCHITECTURE.md) |
| Keep versioned SQL migrations | PostgreSQL triggers, extensions and partial indexes already encode integrity rules. A checksum ledger keeps one migration history. | Schema changes need careful ordering, grants and restore rehearsal. [Database design](DATABASE_DESIGN.md) |
| Use staff JWTs backed by current sessions | Clients get short-lived access credentials while the API can revoke sessions and see current account grants. | Protected requests still perform a database lookup. Pool connections and retain revocation checks. [JWT policy](JWT_AUTHENTICATION.md) |
| Separate clinic and partner entry points | A single weekly aggregate is easier to review and publish. Staff workflows and private patient URLs stay within the clinic boundary. | The partner path needs an extra TLS hop and dedicated trust material. [Gateway design](../api-management/gateway-design.md) |
| Authorize one department per signed proxy context | The supported example claim set for client credentials informed a conservative context-level grant. | Distinct grants within one proxy need a verified application identity. Check the actual claim profile in hosted staging. [Proxy configuration](../api-management/proxy-configuration.md) |
| Use PostgreSQL-backed request budgets | The application retains the same quotas across workers without introducing a second datastore. | Every admitted request can add database writes. Monitor lock waits and use the hosted edge policy for additional protection. [Traffic management](TRAFFIC_MANAGEMENT.md) |
| Pool request connections and narrow SQL projections | The benchmark showed reduced aggregate latency and API CPU with both changes. | A pool reserves connections. Token issuance p99 regressed in the short run and needs follow-up. [Measured comparison](PERFORMANCE_REPORT.md) |
| Use chronological synthetic validation | Offline replay uses prior observations for prediction features. The operational baseline gives a comparison that can be explained. | Synthetic holdout accuracy cannot stand in for a clinic evaluation. [Model methodology](../ml/README.md) |
| Keep deployment preparation and promotion separate | Routine CI builds and tests against disposable fixtures. The manual Choreo deployment workflow targets Development. | Hosted execution, publication and promotion rely on approved environment setup and credentials. [CI/CD pipeline](CICD_PIPELINE.md) |
