# QueueSense technical debt and risk register

**P1** items need a fix or a documented acceptance decision before external exposure. **P2** items should be resolved before making scale or operational readiness claims. **P3** items improve maintainability or address a future scope decision. A code finding identifies behavior present in the repository. A risk describes a plausible impact that needs deployment, concurrency or load evidence.

## Security, privacy and correctness

| ID | Priority | Finding and impact | Proposed action and verification |
| --- | --- | --- | --- |
| SEC-01 | P1 | **Code finding.** The database exception handler logs the raw request path. Patient, appointment and kiosk URLs embed private keys, so a database failure can place credentials in logs even with Uvicorn access logging disabled. Proxy and hosted telemetry behavior is unverified. [Exception handler](../backend/app.py#L107), [private routes](../backend/arrivals.py#L143), [deployment](DEPLOYMENT.md) | Log route templates or a fixed label for unmatched routes. Add log-capture tests using synthetic keys. Verify redaction in every ingress, error and telemetry layer before exposure. |
| SEC-02 | P1 | **Code finding.** The 600/minute patient status cap is an in-memory list per app process and shared across callers. Related QR, doctor and SSE reads do not pass through that cap. PostgreSQL controls login and QR arrivals separately, and the login peer bucket is generally shared behind Next.js. The service proxy also drops upstream retry hints. [Patient status](../backend/product.py#L282), [login](../backend/app.py#L131), [arrivals](../backend/arrivals.py#L158), [service proxy](../frontend/app/api/service/%5B...path%5D/route.ts) | Establish route-specific, multi-replica limits and trusted client identity. Keep narrower application safeguards. Test 429/Retry-After behavior through the actual ingress and concurrent public requests. |
| SEC-03 | P1 | **Code finding with unmeasured impact.** Recovery responses share generic text, but eligible accounts with configured email perform synchronous SMTP while the transaction is open. Provider latency can produce a timing side channel. Recovery request limits are scoped by address/peer pair. [Recovery handler](../backend/accounts.py#L112), [SMTP](../backend/delivery.py#L14) | Move delivery off the response path with a durable asynchronous mechanism and review recovery rate-limit dimensions. Verify equivalent response behavior using mocks and synthetic accounts. |
| SEC-04 | P1 | **Code finding.** Production checks use the exact `APP_ENV=production` value. The app can start without validating the account encryption key. Failure surfaces only when encryption is used and a missing or changed key can disable MFA or delivery operations. Code hashing uses a private Fernet attribute. [Settings](../backend/app.py#L24), [encryption](../backend/security.py#L7), [provider setup](ACCOUNTS_AND_NOTIFICATIONS.md) | Validate deployment profiles, explicit URLs and keys at start, and document backup and rotation. Preserve readability of old ciphertext during migration. Add invalid/omitted configuration and restart tests. |
| SEC-05 | P1 | **Policy gap.** Doctor mutations enforce linked clinician ownership, but shared queue reads accept any staff session. Both queue views include the free-text priority reference. Feedback also accepts free text. Existing UI guidance depends on staff and patients avoiding identifying material. [Queue handlers](../backend/product.py#L194), [paged read](../backend/table_pages.py#L26), [feedback](../backend/experience.py#L37) | Approve a field-level access matrix, retention rules, and a minimal external payload. Test allowed and denied role/scope combinations at FastAPI and the future gateway. |
| SEC-06 | P1 | **Boundary gap.** The Next.js proxies cap browser request bodies and allowlist paths. Direct FastAPI access would bypass those controls. OpenAPI includes staff, recovery and private capability operations and carries no auth schemes. [Proxies](../frontend/app/api), [app factory](../backend/app.py#L88), [route inventory](EXISTING_ARCHITECTURE.md#fastapi-operation-inventory) | Keep the internal API private, publish only an explicit integration allowlist and enforce method, body and auth rules on the external path. Verify direct-origin access and denied routes in staging. |
| COR-01 | P2 | **Concurrency risk.** Schedule creation performs an overlap query before inserting. PostgreSQL only guarantees positive durations and unique start times, so the schema does not prevent differently timed overlaps from other writers. The current HTTP path locks the clinician through `station()`, which serializes the same clinician's API writes. [Schedule creation](../backend/product.py#L428), [staff locking](../backend/product.py#L119), [schedule schema](../database/migrations/001_foundation.sql#L29) | Add a parallel request regression and evaluate a database-level overlap rule if more write paths are introduced. Define how existing overlaps and cancelled shifts would be handled. |
| COR-02 | P2 | **Code finding.** The waiting snapshot and analytics use department-local time while several queue mutations, imports and forecast helpers use Asia/Colombo. This is consistent for the default installation and can diverge if department timezones change. Imported clinician assignment is synthetic. [Queue](../backend/product.py), [metrics](../backend/services/metrics.py), [importer](../backend/services/importer.py), [schema](../database/migrations/001_foundation.sql#L11) | Document the current timezone and historical data contracts. Add midnight boundary tests and define a shared service-date policy before supporting other timezones. Keep imports scoped to the existing synthetic/historical contract until real clinician attribution is specified. |

## Performance and reliability

| ID | Priority | Finding and impact | Proposed action and verification |
| --- | --- | --- | --- |
| PERF-01 | P2 | **Code finding.** Each event stream opens a dedicated PostgreSQL connection for up to roughly 50 seconds and reconnects. Synchronous requests create fresh connections. Streams can consume the database connection budget or trigger reconnect bursts under load. Patient streams listen to department-level change signals. [SSE](../backend/arrivals.py#L183), [connection helper](../backend/app.py#L49), [client hook](../frontend/components/live-updates.ts) | Measure concurrent streams, reconnect rates and peak connections. Evaluate a shared listener per API process and a bounded pool for short requests based on evidence. Preserve reconnect reconciliation. |
| PERF-02 | P2 | **Code finding.** The historical importer can hold the same global transaction lock as queue status changes, close, call-next and availability for up to 5,000 rows. Authentication separately holds a global lock while verifying Argon2. [Queue transitions](../backend/product.py#L214), [import](../backend/services/importer.py#L24), [auth](../backend/app.py#L131) | Capture lock-wait profiles with mixed traffic before narrowing lock scope. Preserve row locking, unique constraints and attempt counting. |
| PERF-03 | P2 | **Code finding.** Waiting-patient reads compute department-wide predictions. Wait-sorted paging fetches and sorts every matching row before slicing. The department board gets a capped 500-row snapshot, and reports run analytics even before a visit-detail query. [Patient status](../backend/product.py#L297), [paging](../backend/table_pages.py#L26), [prediction](../backend/services/prediction.py#L63), [reports](../backend/services/reports.py#L14) | Benchmark large active queues, long date ranges and concurrent exports. Compare bounded work, reusable predictions and streaming when measurements justify them. Protect full-cohort queue position and report correctness. |
| PERF-04 | P2 | **Code finding.** Delivery matches stored notifications and targets repeatedly, then makes sequential provider calls inside a transaction and under an advisory lock. Provider slowness can delay later automation cycles and a crash after provider acceptance can repeat a message. [Delivery worker](../backend/delivery.py#L34), [lifespan](../backend/automation.py#L105) | Keep the durable outbox. Add backlog and job age metrics, test provider failures and worker restarts, and measure separately leased delivery work before changing scheduling. |
| OPS-01 | P2 | **Evidence gap.** Compose has database health and migration completion checks, but no API/frontend healthchecks. Readiness is backed by a DB query and no external metrics, traces or alerts are configured in the repo. The hosted deployment documents have inconsistent verification wording. [Compose](../docker-compose.yml), [health](../backend/app.py#L211), [service probes](../backend/experience.py#L67), [deployment](DEPLOYMENT.md) | Add repeatable container smoke, separate liveness/readiness decisions, dashboards with synthetic evidence, and a verified backup/rollback rehearsal. Record actual environments tested. |

## Duplication, tests and refactoring

| ID | Priority | Finding | Refactoring or test target |
| --- | --- | --- | --- |
| ARCH-01 | P2 | `backend/app.py` mixes app wiring, settings, database access, middleware, auth and route behavior. Feature modules import foundational helpers from it while it imports the feature modules. `backend/product.py` mixes queue, staff, management, analytics and transport. [App](../backend/app.py), [product](../backend/product.py) | Extract stable settings and connection dependencies, then move one cohesive slice to an explicit router. Keep the current app factory entry point, SQL transactions and session behavior. |
| ARCH-02 | P2 | `/queue/live` and `/queue/page` repeat queue selection and decoration. Legacy and paged audit/users endpoints overlap but return different shapes and have different search behavior. [Product](../backend/product.py), [paged endpoints](../backend/table_pages.py) | Retain callers, characterize differences, share query/serialization primitives where semantics match, and migrate consumers only with an explicit compatibility plan. |
| ARCH-03 | P2 | Auth and service proxies duplicate origin/cookie/body-handling logic and differ in status/header forwarding and redirect handling. UI payloads often use `Record<string, any>`. [Auth proxy](../frontend/app/api/auth/%5B...path%5D/route.ts), [service proxy](../frontend/app/api/service/%5B...path%5D/route.ts), [portal](../frontend/components/portal.tsx) | Add a method/path parity check and focused proxy tests for origins, limits, cookies, retry headers, downloads and SSE. Reuse a server helper with explicit per-route policies and adopt typed contracts incrementally. |
| TEST-01 | P2 | CI has good backend/native coverage. The browser job runs `tests/e2e.cjs` only, and npm CI jobs ignore the lockfile. Current load coverage is health and patient status on one worker. [CI](../.github/workflows/ci.yml), [test scripts](../frontend/tests), [load evidence](LOAD_TEST.md) | Select high-value browser cases for appointments, live events, accounts and pagination. Use deterministic installs. Add real container smoke and isolated multi-worker mixed-traffic tests when the runtime is ready. |
| DOC-01 | P3 | Existing documentation has stale account, polling and migration information. It lacks a maintained role/field access matrix, integration lifecycle, secret rotation and per-environment verification ledger. [Backend README](../backend/README.md), [system diagram](architecture/system.md), [data dictionary](../data/data_dictionary.md) | Link to a single source for each contract and record release evidence, ownership, rollback and outstanding manual work. |
| SCOPE-01 | P3 | Departments are site-level subdivisions. The schema and auth queries have no organization-scoped isolation. [Schema](../database/migrations/001_foundation.sql) | Keep the release single-installation unless multi-tenancy is explicitly scoped. Define isolation, migrations and organization membership first if requirements change. |
