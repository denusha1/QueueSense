## Repository and origin

1. Deploy FastAPI privately using the [Service instructions](choreo-integration-plan.md#owner-console-steps-for-the-private-service) or the existing approved host. Apply migrations through 018 and confirm private `GET /health` returns `200`. Place the dedicated HTTPS ingress in front of it and point its upstream at private FastAPI port `8001`. The included [Nginx configuration](integration-ingress.conf) uses private DNS `api`. Adapt that hostname to the private service address assigned by your platform. Use a stable service address or reload the ingress after changing its upstream address. Serve the file as the dedicated ingress's server configuration. Provision a DNS name and a matching TLS certificate, and mount the origin full chain, origin private key and Choreo client trust certificate at the three paths declared in the file. Keep the key in the deployment secret store. A platform ingress may implement the same rules if it can verify the gateway client certificate and enforce the same exact path and method.
2. Once Choreo assigns the proxy context and confirms the issuer, set the five origin variables below in the private FastAPI deployment and redeploy. Keep Development and Production settings independent. Keep the integration route disabled until the HTTPS ingress and Choreo trust material are ready.

| QueueSense variable | Set it to |
| --- | --- |
| `CHOREO_JWKS_URL` | The documented HTTPS backend-assertion JWKS endpoint of the approved gateway, ending in `/.wellknown/jwks`. The official guide lists regional URLs and the private data plane URL pattern. |
| `CHOREO_ASSERTION_ISSUER` | The exact issuer from the verified gateway assertion profile for this environment. |
| `CHOREO_ASSERTION_AUDIENCE` | The environment-specific audience you set under **End User Token Audiences**. |
| `CHOREO_ASSERTION_CONTEXT` | The exact signed `http://wso2.org/claims/apicontext` value observed in a synthetic gateway invocation. Use the assertion's value because the context entry in the Console is only one component of that claim. |
| `CHOREO_DEPARTMENT_ID` | The single approved department UUID in this environment's PostgreSQL database. |

To establish the context for the first deployment, use an approved private diagnostic or controlled staging origin to verify the signed assertion and record only its issuer, audience and context. Keep tokens out of request and diagnostic logs. Replace any staging diagnostic before enabling the live pilot resource. An assertion with an unexpected or omitted context fails closed. [Official backend JWT setup and claims](https://wso2.com/engineering-platform/developer-platform/docs/developer/authentication-and-authorization/pass-end-user-attributes-to-upstream-services/)

## Manual Choreo Console steps

1. In [Choreo Console](https://console.choreo.dev/), select the approved project and choose **+ Create → API Proxy → Upload API Specification**. Upload `openapi.yaml`. Enter a unique name such as `queuesense-weekly-wait`, a context such as `queuesense-weekly-wait`, and version `v1.0`. Set **Target** to the actual HTTPS integration ingress address followed by `/api/integrations/v1`. Confirm **Develop → Resources** contains exactly `GET /wait-time-summary`. The Target contributes the base path once. The imported resource supplies the final path segment. [Official import and resource configuration](https://wso2.com/engineering-platform/developer-platform/docs/develop-components/develop-proxy/develop-an-api-proxy-from-an-open-api-specification/)
2. In **Deploy → Build Area → Security Settings**, keep **OAuth2** and the resource security enabled. Select **Pass Security Context To Backend**, enter the integration audience in **End User Token Audiences**, and apply. [Official assertion settings](https://wso2.com/engineering-platform/developer-platform/docs/developer/authentication-and-authorization/pass-end-user-attributes-to-upstream-services/)
3. In **Develop → Endpoints → Configure**, select the HTTPS endpoint and its server trust settings. Upload the origin certificate where required. Enable **Mutual SSL**, choose **Add Client Certificate → Generate new key pair**, and download the public client certificate via **View and Download**. Make the dedicated ingress trust the approved client certificate, then select the key pair in **Existing Certificates** and save. Avoid sharing that ingress trust between environments or unrelated proxies. [Official mTLS workflow](https://wso2.com/engineering-platform/developer-platform/docs/authentication-and-authorization/secure-communication-between-the-choreo-gateway-and-your-backend-with-mutual-tls/)
4. Leave Request, Response and Error mediation policies empty. QueueSense accepts query parameters unchanged and emits its own status, safe JSON and `X-Request-ID`. The ingress forwards these responses and preserves the origin's cache controls. Choreo may generate a separate rejection or unavailable response before FastAPI handles a request. Capture gateway status, headers and body in testing before adding any policy. [Official proxy policy flows](https://wso2.com/engineering-platform/developer-platform/docs/api-management/api-policies/attach-and-manage-policies/)
5. In **Deploy → Build Area → Configure & Deploy**, verify the Development Target and mTLS certificate. Select the access mode approved for the pilot. **External** makes the secured gateway publicly reachable and requires explicit approval. Deploy, wait for **Development → Active**, then use **Test → OpenAPI Console** and a separate approved machine credential for the [gateway test matrix](gateway-testing.md). Copy the actual invocation address from the Console's endpoint details. [Official deployment and testing](https://wso2.com/engineering-platform/developer-platform/docs/tutorials/expose-a-service-as-a-managed-api/)
6. Keep the lifecycle in **Created** during verification. Owner approval is required for an external access mode, certificate provisioning, API subscription credentials, Production promotion and portal publication. Apply the same mapping and security verification with Production-specific settings before it receives any traffic. [Official lifecycle workflow](https://wso2.com/engineering-platform/developer-platform/docs/api-management/lifecycle-management/)
